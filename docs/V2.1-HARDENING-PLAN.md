# v2.1 Contract Hardening Plan

> **Status:** Planned — deferred from the v2.0.0 release.
> **Scope:** `contracts/**`, `test/contracts/**`, plus the ABI/protocol follow-through in `src/`.
> **Why deferred:** v2.0.0 delivers the full backend, frontend, DevOps and documentation rewrite.
> Several fixes below change ABI-visible signatures, so they must land as one coherent contract release
> rather than racing the backend that transcribes those signatures.

## How these were found

Three independent adversarial reviewers (exploit, correctness, and spec-fidelity lenses) audited the
freshly written contract suite and returned **21 findings**. After removing duplicates reported by more
than one reviewer, **12 distinct issues** remain: 1 critical, 5 high, 4 medium, 2 low.

The critical finding was independently re-verified by hand against `contracts/MemoryLedger.sol` before
being accepted — it is not a false positive.

**These issues exist in the shipped v2.0.0 contracts.** They are disclosed in `docs/SECURITY-NOTES.md`
and the README rather than concealed. The suite is testnet-only and unaudited.

---

v2.1 is not done until all of the following hold:

- [ ] A second adversarial review round returns no new critical/high findings
- [ ] `docs/PROTOCOL.md`, `docs/SECURITY-NOTES.md` and README claim tables updated to match the code

## Phase 1 — Ownership integrity (blocks everything else)

### NM-01 · CRITICAL · CID front-running / squatting

**File:** `contracts/MemoryLedger.sol:143` (`commitMemory` → `_commit`)

Ownership of a CID is first-come-first-served and the contract cannot verify that the committer produced
the content. Agent A pins a memory and receives CID X; any registered agent observing X (mempool, or simply
reading A's public pin) commits it first and permanently owns the on-chain record. A is then locked out by
`MemoryAlreadyExists`, and revocation is owner-only.

This defeats the protocol's central proof-of-ownership claim. `commitMemoryFor` is safe — ownership follows
the recovered EIP-712 signer — but `commitMemory` preserves the original vulnerable primitive, and it is the
path the node actually uses.

**Fix — commit–reveal:**

```
precommit(bytes32 blindedHash)   // blindedHash = keccak256(abi.encode(cidHash, agent, salt))
                                 // leaks nothing about the CID
commitMemory(input, salt)        // requires a matching precommit from msg.sender,
                                 // at least MIN_PRECOMMIT_DELAY blocks old
```

An attacker cannot forge an earlier precommit for a CID first seen at reveal time.

**Alternative considered:** delete `commitMemory` entirely so every commit carries an EIP-712 authorisation.
Simpler, but forces a signature round-trip for the common self-commit case.

**ABI impact:** additive (`precommit`) + `commitMemory` gains a `salt` parameter — **breaking**.
**Effort:** M · **Tests:** front-run attempt reverts; honest precommit→reveal succeeds; reveal before
`MIN_PRECOMMIT_DELAY` reverts; salt reuse reverts.

## Phase 2 — Reputation economics

### NM-02 · HIGH · Endorsement stake is unslashable

**File:** `contracts/ReputationManager.sol:415` (`slashEndorsement`)

`slashEndorsement` requires a live edge, but `revokeEndorsement` is permissionless and instant with no
cooldown. An endorser front-runs the slasher, revokes, and recovers 100% of the stake. Slashing can never
be enforced against anyone paying attention.

**Fix:** make revoked-but-unclaimed edges slashable —
`if (e.createdAt == 0 || e.slashed || e.stakeClaimed) revert NotEndorsed(from, to);`
Only run `_removeEndorsement` when `e.revokedAt == 0` (an already-revoked edge has had its mass and
`endorserCount` removed; re-running teardown would double-decrement). Then
`e.slashed = true; treasuryBalance += e.stake;`.

**ABI impact:** none · **Effort:** S · **Tests:** revoke-then-slash still confiscates; `claimStake` refuses
a slashed edge; `endorserCount` is not double-decremented.

### NM-03 · HIGH · Reports are free, unstaked, permanent and unremovable

**File:** `contracts/ReputationManager.sol:317` (`reportAgent`)

Registration is permissionless and free; `endorsementStakeWei` applies only to endorsements; no role can
undo a report (`SLASHER_ROLE` covers endorsements only, and `withdrawReport` is reporter-only). One
throwaway identity permanently destroys any agent's trusted status. This is the cheapest attack in the
system.

**Fix:** (1) add `reportStakeWei`, escrowed on the Report struct with the same claim/lock/slash lifecycle;
(2) add `slashReport(address from, address to, bytes32 reason)` under `SLASHER_ROLE` running the
negative-mass teardown and confiscating the stake; (3) consider report expiry so stale reports decay.

**ABI impact:** additive + `reportAgent` becomes payable — **breaking**.
**Effort:** M · **Tests:** unstaked report reverts; slashed report restores the target's score; expiry.

### NM-04 · HIGH · Decay is defeatable by frequent settling

**File:** `contracts/ReputationManager.sol:768` (`_settle`)

`DecayMath.decayFactor` quantises to 1/16-half-life buckets, so it returns `WAD` (no decay) for any elapsed
time under `halfLife/16` — **5.625 days** at the 90-day default. `_settle` nevertheless sets
`_lastSettledAt = block.timestamp` unconditionally, discarding the unapplied elapsed time. Calling `settle`
more often than once per bucket freezes an agent's score forever. `settle` is permissionless.

**Fix:** advance the clock only by the time the quantised factor actually consumed, carrying the residual:

```solidity
uint256 hl = halfLifeSeconds;
uint256 applied = hl == 0 ? dt : (dt / hl) * hl + ((((dt % hl) * 16) / hl) * hl) / 16;
_lastSettledAt[agent] = uint64(last + applied);
```

**ABI impact:** none · **Effort:** S · **Tests:** 100 rapid settles decay identically to one settle over the
same total interval.

### NM-05 · HIGH · Documented sybil bound is false (8 wallets, not 18)

**File:** `contracts/ReputationManager.sol:77-82` (header NatSpec)

The NatSpec claims an attacker needs 18 distinct endorsers because "each fresh, zero-reputation endorser
contributes only 0.25". That assumes sybil endorsers stay at reputation 0, but `previewEndorsementWeight`
reads the endorser's _live_ reputation and nothing normalises outgoing weight. Clique members bootstrap each
other, halving the real cost to **8 mutually-endorsing wallets**.

**Fix:** implement outgoing-row normalisation (cap an endorser's total outgoing weight at `w(i)`, split
across targets) per the protocol spec, **or** freeze re-endorsement weight and compute contributions from a
lagged/settled reputation excluding same-clique edges. Then correct the NatSpec to the measured bound.

**ABI impact:** none (behaviour + docs) · **Effort:** L — this is a trust-model change, not a patch.
**Tests:** the existing 18-wallet sybil test must be joined by an 8-wallet clique test asserting the target
does **not** become trusted.

## Phase 3 — Moderation and access control

### NM-06 · HIGH · Suspended agents can self-reinstate

**File:** `contracts/AgentIdentity.sol:195` (`reactivate`)

`adminSetActive` and `reactivate` write the same `active` flag, and `reactivate` only checks
`exists && !active` — it has no notion of _who_ deactivated the agent. A `REGISTRAR_ROLE` suspension is
undone by the agent in the very next transaction. Moderation is unenforceable.

**Fix:** record the authority of the last status change (`bool suspendedByRegistrar`, or
`address statusChangedBy`), set it in `adminSetActive`, and have `reactivate()` revert with a new
`SuspendedByRegistrar(address)` error while set. Only `adminSetActive(agent, true, reason)` clears it.

**ABI impact:** additive error + struct field · **Effort:** S
**Tests:** registrar-suspended agent cannot self-reinstate; self-deactivated agent still can.

### NM-07 · MEDIUM · Expired grants block re-granting

**File:** `contracts/MemoryAccessControl.sol:304` (`_grant`)

`_grant` treats expired grants as still active, so a grant can never be renewed after expiry.

**Fix:** treat `expiry != 0 && expiry <= block.timestamp` as inactive in the duplicate check.
**ABI impact:** none · **Effort:** S

### NM-08 · MEDIUM · Escrowed stake unreachable during a pause

**File:** `contracts/ReputationManager.sol:295, 386`

`claimStake` is deliberately pause-exempt, but its precondition `revokeEndorsement` is not — so pausing
freezes every endorsement stake, contradicting the exemption's intent.

**Fix:** make `revokeEndorsement` pause-exempt, or add a pause-exempt `emergencyRevokeAndClaim`.
**ABI impact:** none or additive · **Effort:** S

### NM-09 · MEDIUM · `withdrawTreasury` ignores the `treasury` variable

**File:** `contracts/ReputationManager.sol:433`

Sends slashed ether to an arbitrary caller-supplied address; the `treasury` state variable is never read and
therefore grants nothing. `setTreasury` is misleading.

**Fix:** send to the stored `treasury`, or remove `treasury`/`setTreasury` entirely.
**ABI impact:** signature change — **breaking** · **Effort:** S

## Phase 4 — Protocol conformance

### NM-10 · HIGH · On-chain EIP-712 does not match the normative spec

**Files:** `MemoryLedger.sol:82,127`, `AgentIdentity.sol:88`, `MemoryAccessControl.sol:108`

Implemented: three domains — `("NeuroMeshMemoryLedger","1")`, `("NeuroMeshAgentIdentity","1")`,
`("NeuroMeshAccessControl","1")`. The protocol spec is normative for one domain `("NeuroMesh","2")` with
`specHash` on every struct and different field names (`Registration`→`AgentRegistration`, `owner`→`grantor`,
`expiresAt`→`expiry`, `cidHash`→`scope`, `wrappedKeyHash`→`wrappedKeyDigest`).

**This is an unresolved cross-lane conflict, not a typo.** The two source specs disagree, and the contracts
implement one of them consistently. The system works end-to-end today because the backend transcribes from
the contracts. It only breaks third-party clients written against `docs/PROTOCOL.md`.

**Decision required before v2.1 ships.** Recommendation: adopt the spec verbatim (single domain, add
`specHash`) so external clients interoperate, and regenerate `src/protocol/eip712.js` from the contracts.

**ABI impact:** all typehashes change — **breaking for every existing signature** · **Effort:** M
**Tests:** digests must equal an independent `ethers.TypedDataEncoder` computation and the contract's
`hashCommit` view.

### NM-11 · MEDIUM · Verification-binding fields are not recorded

**File:** `contracts/MemoryLedger.sol:415`

None of `payloadHash`, `cidDigest`, `modelId`, `alignmentId`, `policyId` are stored, so the third-party
verification procedure in `docs/PROTOCOL.md` cannot actually be executed against chain state.

**Fix:** add the missing fields to `MemoryRecord` and the commit struct (bundle with NM-10's breaking change).
**ABI impact:** breaking · **Effort:** M

### NM-12 · LOW · `DecayMath` NatSpec understates its own error ~30×

**File:** `contracts/libraries/DecayMath.sol:25`

Documented quantisation error is 0.15%; measured is **4.39–4.43%**, and it always biases scores _upward_
(agents keep more reputation than they should).

**Fix:** correct the NatSpec, or add interpolation within buckets to actually achieve the documented
accuracy. Also remove the two unreachable custom errors in `NeuroMeshErrors.sol:59`.
**ABI impact:** none · **Effort:** S

## Note on deployment

The Sepolia addresses in `contract-addresses.json` are **pre-rewrite v1 contracts**. Their ABI does not match
the v2.0.0 suite. The backend detects this and reports `contractsCompatible: false` while continuing to serve
read-only routes. A v2.1 deploy should write `deployments/11155111.json` via `npm run deploy:sepolia` and
verify with `npm run verify`.
